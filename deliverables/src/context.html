Inside the system: components, data flow and trust gates

How the parts connect when a planner runs and approves a plan. The optimisation core has no web or database code; the API layer has no calculation logic.

One run, step by step

1 Validate. Files parsed, checked by file and row. Errors stop here.
2 Baseline. Preferred-warehouse rule builds the comparison plan.
3 Optimise. LP or MILP finds the lowest-cost plan; status recorded.
4 Verify. Separate checker re-tests both plans against every rule.
5 Compare. Cost by type, load per warehouse; saving only if baseline valid.
6 Store. Run and audit event saved; planner reviews and decides.
